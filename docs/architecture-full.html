2. Data model — farmer vs research

Farmer-owned (their data)

  • User → account (email, bcrypt hash)
  • Farm → owned by user
  • Camp → paddock: area, livestock, coords, grazing dates
  • Assessment → verdict + evidence JSON snapshots
  • CampPhoto → uploads + cached vision analysis
  • ChatMessage → advisor history

Research corpus (never claimed as the camp)

  • ~70 reference plots (cover, biomass notes, ecoregion)
  • ~236 cover rounds · ~53 species rows
  • ~888 photo metadata records
  • Loaded from reference_seed.json (no raw 4GB dataset needed)
  • Always framed as comparable research observations

Honesty rule: research plots are matched by distance/ecoregion for context only. The UI and prompts must never present them as the farmer’s own measurements.

3. End-to-end assessment flow

Farmer picks a camp → enters / confirms livestock → optional photos → Run assessment
  1. POST /api/assessments — auth + camp ownership check; optional herd update
  2. assessment_service.create_assessment calls the agent
  3. Agent gathers evidence via tools (or rule engine if AI unavailable)
  4. Structured verdict: status, direct answer, recommendation, reasons, evidence, confidence, limitations, next steps
  5. Saved to assessments with snapshots: herd, weather, references, calculations, photo findings, engine name
  6. Returned to website / mobile for display; farmer can follow up in Advisor chat

4. How the AI agent works

Tool-calling loop

  • Model: Gemini via OpenAI-compatible SDK
  • Up to 8 tool rounds (MAX_TOOL_ROUNDS)
  • tool_choice=auto; last round forces submit_assessment
  • Final output is a function call — not free-form JSON
  • Statuses: Good · Watch · High concern · Insufficient data
  • Confidence: Low · Moderate · High

Prompt framing

  • Separate farmer data, weather, research, photos, calcs, AI conclusions
  • Cautious language (“may indicate”, “based on available evidence”)
  • Photos never invent exact biomass / grass % / grazing days left
  • Missing weather: say so and continue
  • Low confidence → recommend field inspection / extension officer

6. How decisions are made

GoodCamp can currently sustain the herd under available evidence.
WatchEarly pressure or decline — monitor and plan changes.
High concernStrong overgrazing / drought stress signals — act soon.
Insufficient dataNot enough evidence to judge responsibly.

A) Gemini path (preferred)

  1. Model chooses which tools to call
  2. Builds evidence items labelled by source
  3. Calls submit_assessment with status + confidence
  4. Backend overlays tool snapshots onto the saved row

If the loop ends without submit, or the LLM errors → fallback.

B) Rule-based fallback (always available)

Used when no API key, LLM fails, or tools never submit.

  • Always computes LSU/ha, grazing days, weather, comparable plots (+ photos if any)
  • Adds a concern score from thresholds below
  • Maps score → status with template recommendations

7. Fallback scoring rules (transparent thresholds)

Livestock pressure

  • LSU/ha ≥ 0.25 → concern +2
  • LSU/ha ≥ 0.12 → concern +1
  • Below that → low pressure
  • Missing area → limitation (no LSU/ha)

Rainfall (30-day)

  • < 10 mm → +2 (or +1 if no herd)
  • < 40 mm → +1 (if herd)
  • Else → reasonable rainfall reason
  • Weather unavailable → continue, note it

Plots & photos

  • Avg grass cover of refs < 25% → +1
  • Photo grass = sparse → +1
  • Photo exposed soil = high → +1

Status mapping from concern score

  • No known signals → Insufficient data (Low confidence)
  • No herd (rested): concern ≥ 2 → Watch, else Good
  • With herd: concern ≥ 4 → High concern; ≥ 2 → Watch; else Good
  • Next steps always include walk-the-camp; extension officer if Watch / High concern with a herd

8. Photos, chat, and offline clients

Photos (vision)

  • Optional; strengthen, never replace other evidence
  • Buckets only: grass density, dryness, exposed soil, woody density, erosion signs
  • Analysis cached on CampPhoto
  • No LLM → all “uncertain”

Advisor chat

  • POST /api/chat — same tools, no submit_assessment
  • Free-text reply; last 8 history turns
  • Needs Gemini (no rule-engine verdict)
  • Persists user + assistant messages

Offline (shared client)

  • Cache farms, camps, past assessments
  • Queue camp create/update offline
  • Online-only: login, assess, chat, photos, weather
  • Read timeout ~18s · write ~90s
